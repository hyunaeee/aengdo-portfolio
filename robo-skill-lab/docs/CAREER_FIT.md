확인일: **2026-09-15 (Asia/Seoul)**. 기존 포트폴리오 파일과 회사 공식 채용 페이지를 확인했다. 공고의 요구사항과 이 프로젝트의 설계 해석을 구분하며, 아래 내용은 합격 가능성이나 지원 자격 충족의 판정이 아니다. 구현·실행 결과의 최신 상태는 프로젝트 README와 실제 보고서를 따른다.

## 1. 추천하는 연결점

**자연어 지시를 로봇 작업으로 바꾸고, 실행 결과를 관찰해 실패를 복구하며, 개선 여부를 실험으로 보여주는 프로젝트**를 만든다.

예시 지시는 “빨간 블록을 오른쪽 목표 지점으로 밀어줘”다. CPU에서 실행하는 MuJoCo 탁상 환경으로 시작한다. 작업 해석, 동작 실행, 완료 판정, 재시도를 각각 확인할 수 있게 만들어 기존의 에이전트·비전·평가 경험을 물리 환경으로 확장한다.

이 방향은 현재 포트폴리오에서 확인되는 강점을 활용한다.

| 기존 근거 | 이번 프로젝트에 연결할 증거 |
|---|---|
| MED-RAG의 검색·응답 평가 분리, 합성 사례 평가, QLoRA 실험 및 라벨 감사 | 자연어 해석 정확도와 물리 작업 성공률을 따로 측정하고, 실패 원인을 해석·제어·관측 단계로 나누기 |
| Terracotta·Meeting Assistant의 에이전트 연결과 제품 구현 | 언어 지시를 검증 가능한 작업 명세로 변환하고, 실행 상태·오류·중단을 기록하기 |
| VisionEye의 검출기·추적기 비교, 원본/결과 동기화, 단계별 지연 측정 | 같은 초기 조건에서 제어 방식을 비교하고, 시뮬레이션 영상과 상태 기록을 함께 검수하기 |
| VisionEye Model Server의 실제 CPU 추론, 동시 요청 제한, worker 장애·복구 검증 | 관측 실패, 시간 초과, 목표 미달을 구분하고 복구 정책을 재현 가능한 실험으로 검증하기 |
| Venue Atlas·3D 장면 작업 | 로봇 상태·목표·경로·접촉을 읽기 쉬운 3D 화면으로 전달하기 |

## 3. 면접에서 보여줄 핵심 실험

다음 항목은 **실험 설계안**이며, 실행 전 수치를 성과로 쓰지 않는다.

1. **동작 원리:** 자연어 → 제한된 작업 명세 → 스킬 선택 → MuJoCo 물리 실행 → 현재 상태 확인 → 성공 판정 또는 재계획.
2. **기준 방식:** 최초 계획을 그대로 실행하는 방식과, 실행 중 관측해 수정하는 방식을 같은 seed·초기 상태·목표에서 비교한다.
3. **어려운 조건:** 물체 초기 위치와 마찰을 바꾸고, 실행 중 블록 위치에 외란을 주어 접촉을 잃거나 목표에서 벗어나는 사례를 만든다. 정상과 외란 조건을 별도 집계한다.
4. **지표:** 목표 반경 내 정지 성공률, 최종 위치 오차, 시뮬레이션 시간, 재시도 횟수, 실패 유형. CPU wall-clock 시간과 시뮬레이션 시간을 구분한다.
5. **재현 자료:** seed·환경 설정·명령·제어기 버전·상태 궤적·요약 JSON·실패 영상. 동일 seed의 비교는 짝지은 비교로 설명하며, 반복 재생을 독립 표본으로 세지 않는다.

MuJoCo는 관절 구조와 환경의 접촉을 다루는 물리 엔진이며 Python 바인딩을 제공한다. 이 프로젝트에서는 실제 엔진의 상태·접촉 결과를 평가의 근거로 사용한다. 출처: [Google DeepMind MuJoCo 저장소](https://github.com/google-deepmind/mujoco).

## 4. 단계별 확장과 표현 범위

| 단계 | 완성할 내용 | 정확한 표현 |
|---|---|---|
| CPU 출발점 | 물리 접촉으로 블록 밀기, 명령 파서, 재계획, 반복 평가 | “MuJoCo 기반 로봇 작업 실행·복구 프로토타입” |
| LLM 연결 | 모델이 작업 명세를 만들고 스키마·작업 가능성을 검증, 기록된 명령셋으로 파서와 비교 | 실제 모델 호출을 측정한 뒤 “LLM 기반 작업 계획” |
| 비전 연결 | 렌더 이미지로 위치를 추정하고 MuJoCo 정답 상태와 관측 오차를 비교 | 실제 이미지 처리 후 “비전 기반 관측”; 정답 좌표를 쓰는 단계는 “시뮬레이터 상태 관측” |
| 학습 정책 | 수집한 궤적에서 모방학습하고 분리한 평가 조건에서 기준 제어기와 비교 | 실제 훈련·평가 후 “학습 기반 제어” |
| 실제 로봇 | ROS2/실물 인터페이스, 교정, 제한된 작업 공간에서 별도 검증 | 실물 실행을 검증한 뒤 “Sim-to-Real” |

초기 명령 해석이 규칙 기반이면 그렇게 표시한다. 임의의 텍스트 입력창만으로 LLM·VLA라고 부르지 않는다. 물리 상태를 읽는 초기 실험은 비전 모델의 인지 성능을 증명하지 않는다. 학습하지 않은 제어기를 강화학습 정책이라고 부르지 않는다.

## 5. 지원 시 한 문장

**프로젝트 방향:** “기존 LLM 에이전트·비전 평가 경험을 로봇 작업 실행으로 확장해, MuJoCo에서 언어 지시·상태 관측·실패 복구를 연결하고 조건별 성공률을 비교하는 실험 환경을 개발하고 있습니다.”

완료된 기능과 실제 보고서가 생기면 현재형을 완료형으로 바꾸고, 측정한 표본 수·조건·성공률만 덧붙인다. 특히 처음에는 Robotics AI Software, Applied AI, Simulation/Evaluation, ML Platform 역할과 연결해 설명하고, 학습 기반 제어 연구 역할에는 추가 실험이 필요한 부분을 명확히 제시한다. 이 우선순위는 기존 작업과 위 공고를 비교한 설계 판단이다.
