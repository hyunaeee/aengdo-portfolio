01 / WORKFLOW

프로젝트 개요

CLI 도구에서 시작해 웹 UI와 Docker 서비스로 확장했습니다. 녹음 이후의 전사, 발언자 구분, 회의록 작성과 공유를 한 흐름에서 다루도록 만들었습니다.

02 / SYSTEM

시스템 구조

현재 RTX 4090에서 운영합니다. 공개 데모는 동일한 작업 흐름을 샘플 데이터로 보여주며, 실제 음성 처리와 외부 API 호출은 사내 서비스에서 수행합니다.

  1. 01음성

    faster-whisper

  2. 02화자 분리

    pyannote · RTX 4090

  3. 03회의록

    Claude · structured JSON

  4. 04저장·전달

    Notion · SMTP

03 / PERFORMANCE

평가 결과

기존 기록의 “56분 파일, 약 28초”는 청크 방식 화자 분리 단계의 사례입니다. 전사·요약·저장까지 포함한 전체 시간이나 반복 벤치마크로 해석하지 않습니다.

운영 성능을 설명할 다음 근거는 단계별 지연, 화자 분리 품질, 실패·재처리 비율입니다. 현재 사용 중인 서비스를 보존하면서 별도 환경에서 측정을 준비합니다.

04 / ACCESS

SSO와 접근 권한

Google SSO와 사용자·부서별 열람 범위를 작업 흐름에 연결했습니다. 공개 화면과 사내 데이터를 분리해 제품을 체험할 수 있도록 했습니다.

ENGINEERING DECISIONS

설계 판단

01

GPU 작업과 외부 서비스를 연결

음성 처리와 화자 분리는 로컬 GPU에서 수행하고, 구조화한 회의록을 후속 저장·전달 단계로 연결했습니다.

02

화면보다 먼저 권한을 설계

로그인한 사용자와 부서별 접근 범위를 고려해 회의록을 조회하게 구성했습니다.

03

전체 시간과 단계별 시간을 분리

화자 분리 개선 수치를 회의록 전체 처리 시간으로 표현하지 않습니다. 입력 길이, 실행 환경, 처리 단계를 함께 기록합니다.

SCOPE & LIMITS

한계와 검증 범위

  • 사내 코드·회의 데이터는 공개하지 않습니다. 데모의 음성과 결과는 샘플입니다.
  • 처리 단계의 사례 수치를 전체 서비스 SLA로 표현하지 않습니다.
