검증된 신원에서 소유권으로

OIDC 토큰 서명과 issuer·audience·nonce·만료를 검증합니다. 계정 식별자는 검증된 Google subject에 연결하며, 프로젝트·이벤트·다운로드·취소·재시도 경로에 소유권 검사를 적용합니다.

키와 상태의 보관 범위

개인 API 키는 AES-GCM으로 암호화합니다. 다른 계정으로 전환하거나 다른 브라우저에서 로그인해도 원래 계정의 키가 타인에게 전달되지 않는지 테스트합니다.

선택이유
Node.js · ExpressHTTP API와 생성 작업의 제어 로직을 분리해 검증하기 위해 사용했습니다.
소유자별 API 검사화면에서 숨기는 것에 더해 요청 경로에서 다른 계정의 결과 조회와 실행 제어를 거절합니다.
외부 서비스 주입실제 결제나 모델 호출 없이 인증 검증·라우팅·권한 회귀를 반복할 수 있도록 구성했습니다.

계정 소유권 검증이며 기업 조직별 멤버십·RBAC 구현으로 확대해 설명하지 않습니다. 실제 Google·Vercel 연동 운영 검증은 별도 범위입니다.

결제 승인 요청이 중복되거나, 이용권 기록 응답이 유실되거나, 질문 처리와 환불이 겹칠 수 있습니다. 이때 결제·이용권·사용 횟수의 상태가 서로 어긋나지 않도록 설계했습니다.

  2. 02승인 선점 · 멱등키

경계구현한 선택
동일 주문 승인Redis Lua로 처리 소유권을 선점하고 외부 결제 승인에 주문별 멱등키를 사용합니다.
이용권 중복 지급승인 상태와 권한 부여를 원자적으로 검사·변경합니다.
질문 횟수 차감잔여 횟수 차감과 진행 중 질문 수 변경을 같은 Lua 실행에서 처리합니다.
질문 처리 중 환불환불 선점과 진행 중 작업 조건을 검사해 허용되지 않는 충돌을 거절합니다.
기록 응답 유실기록 실패를 즉시 결제 실패로 단정하지 않고 원장을 다시 조회해 상태를 대조합니다.

핵심 불변 조건

  • 한 주문의 구매 권한은 한 번만 부여됩니다.
  • 동시 요청에서도 사용 가능 횟수를 초과하지 않습니다.
  • 동일 환불의 외부 취소 호출은 중복되지 않습니다.

구현 범위

구매 권한과 사용량의 일관성을 다루는 개인 프로젝트입니다. 기업 조직 권한, 실제 거래 규모, 운영 매출의 근거로 사용하지 않습니다.

공개 UI는 결제 없는 데모입니다. 결제 백엔드 소스의 공개 접근은 별도 확인이 필요하며, 아래 검증 설명은 확인한 코드와 테스트에 한정합니다.

03 / 천기연 · Concurrency verification

정상 결제 한 건을 넘어
실패와 경쟁 조건을 검증합니다.

기존 테스트는 Redis·Toss·Claude를 대체한 환경에서 348개 항목을 검사합니다. Redis Lua는 VM에서 실행해 제어 로직을 확인하며, 별도 실제 Redis 7.4.11에서 7개 시나리오(상위 테스트 포함 8개)가 통과했습니다. 승인 16건·권한 부여 24건·환불 16건의 동시 요청과 질문·환불의 두 선행 순서를 검증했습니다.

실험확인한 불변 조건
동일 승인 병렬 요청외부 승인과 이용권 지급이 중복되지 않음
잔여 5회에 질문 20건허용된 횟수만 시작되고 잔액이 음수가 되지 않음
동시 환불 요청외부 취소가 한 번만 실행됨
질문 완료 재전송진행 중 작업 수가 중복 감소하지 않음
Redis 기록 응답 유실원장 재조회 후 이미 부여한 권한을 다시 지급하지 않음

반복 가능한 검증

각 테스트의 Redis 키는 고유 접두사를 사용합니다. 실제 서비스 키·주문·외부 결제 자격 증명을 읽지 않는 전용 환경으로 실행합니다.

주장을 구분하는 기준

대체 환경 테스트, 실제 Redis 실행, 결제사 테스트 환경, 실제 거래 운영을 별도 단계로 기록합니다. 통과 개수를 거래 성공률로 바꾸어 설명하지 않습니다.

기존 검증 기준 소스: e560ee5. 실제 Redis 통합 검증 및 CI 변경은 지원 준비 작업에서 추가한 별도 변경이며 운영 배포와 구분합니다.
